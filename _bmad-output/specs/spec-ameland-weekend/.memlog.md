- (why) Tim (organizer) is running a secret, hype-building surprise trip to Ameland (2-4 Oct 2026) for 7 friends; the site paces the reveal chapter by chapter so guests don't know the full plan up front, culminating in push notifications the moment the organizer reveals something new. A vision-to-realize plus a mandate: the real build must be ready for a compagnon (co-organizer) review checkpoint on 2026-09-14 before the group link goes out. The design/UX (Claude Design canvas mockups) is done; this spec covers turning that into the real, reusable PWA.
- (capability) CAP-1 Installable PWA — intent: a guest can install the site to their phone's home screen so push notifications work. success: a real web app manifest + service worker exist; Android/iOS install instructions render per-platform (as in Main.dc.html); an installed icon appears on the home screen and push permission can be granted from it.
- (capability) CAP-2 Progressive chapter reveal — intent: a guest sees only the chapters the organizer has unlocked; a locked chapter shows the existing placeholder, never its real content. success: per architecture AD-2, a locked chapter's title/description/time/location/illustration never appears in the page source or network response until the organizer unlocks it; unlocking flips visibility on already-open tabs without a manual reload (AD-4).
- (capability) CAP-3 Push notification on unlock — intent: every subscribed guest is notified the moment the organizer reveals a new chapter. success: toggling a chapter unlocked in the admin view triggers a push within the same request (AD-4); an installed device shows the OS notification and, on tapping it or if already open, sees the revealed content.
- (capability) CAP-4 Organizer admin view — intent: the organizer always sees the full trip (every chapter, including locked ones) and can toggle each chapter's unlocked state independently. success: the admin page (passcode-gated, AD-5) renders all chapters unredacted with working per-chapter toggles, matching Admin.dc.html's row layout and always-on Paklijst row.
- (capability) CAP-5 Shared packing list — intent: any participant can check off packing items from a shared list, visible to everyone, independent of any chapter's lock state. success: the packing list always renders in full even before any chapter unlocks; a check/uncheck by one participant is visible to the others (AD-6); concurrent edits resolve deterministically (set-state, not toggle).
- (capability) CAP-6 Tiered chapter treatment (cinematic vs knap) — intent: Bestemming, Blokarten, and Brouwerij get full grandeur scroll-triggered SVG/text choreography; Vrijdag and Zondag stay polished-but-restrained; any cinematic chapter is replayable via a 'Bekijk opnieuw' button. success: the shipped build reproduces Main.dc.html's reveal/cinematic-reveal/staggered-delay CSS system and triggerPulse replay mechanism unchanged, and respects prefers-reduced-motion by snapping every animated element to its end state.
- (capability) CAP-7 Reusable trip template — intent: standing up a future trip requires only authoring a new content entry, never a code change. success: a second trip can go live by adding a new TripContent entry (per architecture AD-7) with its own slug/accentColor/chapters/packingList — no route, component, or schema code is touched to do it, aside from a genuinely new illustration treatment (AD-7 exception, already a named non-goal-adjacent case).
- (constraint) v1 is one-way only: the organizer publishes/unlocks, guests consume. Two-way interaction (comments, photo uploads) is explicitly out of scope for this spec (see Non-goals) — this rules out building any guest-writable content endpoint beyond the packing list and push subscription.
- (constraint) Admin access is a single shared passcode (env var) with a long-lived signed cookie and per-IP throttling (architecture AD-5) — this rules out building any user-account/OAuth system for the organizer.
- (constraint) Only three things are ever server-mutable state: chapter unlocked flags, push subscriptions, and packing-list checked state (architecture AD-1/AD-7). This rules out storing any other trip content in a database — chapter copy, timing, and illustration choice must be static authored content.
- (constraint) Stack is pinned by the adopted architecture spine: Astro (latest 7.x), hand-written manifest/service worker, PushForge for VAPID push, Vercel Functions (Node runtime), Neon Postgres via the Vercel Marketplace integration (architecture Stack + AD-8/AD-9) — this rules out picking a different framework, hosting platform, or push library without first amending the architecture spine.
- (constraint) The existing CSS/animation system in Main.dc.html (reveal/cinematic-reveal classes, staggered delays, SVG line-draw, the persistent fixed-position viewfinder layer, the replay mechanism) is the visual/interaction source of truth and must transfer into the real build unchanged — this rules out redesigning the motion system or reimplementing it from scratch in a different style.
- (constraint) The compagnon-review checkpoint is 2026-09-14 (visible in Admin.dc.html's own review-gate bar): the group link only goes out to the other 5 friends after that review passes — this rules out treating the build timeline as open-ended; the working build (or a close approximation) needs to exist before that date.
- (non-goal) Two-way guest interaction (comments, photo/video uploads) is explicitly out of scope for this spec — a deliberate v2 extension per BUILD_BRIEF, not an oversight.
- (non-goal) Per-guest identity or accounts are out of scope — packing-list state is shared/trip-wide (AD-6), and there is no login for guests, only the organizer's shared admin passcode.
- (non-goal) Real photo/video assets are out of scope for v1 — the hand-drawn SVG line art in the current mockups ships as-is; swapping in real media is a future content update, not a v1 build task.
- (non-goal) A standalone MP4 teaser video (the previously-explored hyperframes Node/FFmpeg/headless-Chrome render pipeline) is out of scope — it would be a separate offline tool, not part of the PWA build.
- (non-goal) An automated test suite is out of scope for v1 (architecture Deferred) — verification is manual QA against this spec's success criteria before the 2026-09-14 checkpoint.
- (non-goal) Multi-organizer or multi-tenant support is out of scope — this spec covers exactly one project, one organizer, trips added as new content entries.
