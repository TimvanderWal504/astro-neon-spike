- (constraint) Reusable-template requirement (from BUILD_BRIEF.md): content/config must be trip-scoped data, never hardcoded per trip — a future trip is a new content entry, not new code.
- (constraint) MVP is one-way (organizer publishes); two-way interaction (comments/photo uploads) is explicit v2 scope, not this build.
- (constraint) Packing list must always render regardless of any chapter's unlocked state — never gated behind the reveal system (BUILD_BRIEF 'alwaysOn').
- (constraint) Cinematic chapters (Bestemming, Blokarten, Brouwerij) get full grandeur SVG/animation treatment; other chapters (Vrijdag, Zondag) stay 'knap' (polished, restrained) — new chapters must be classified into one of these two tiers, not a third.
- (constraint) Cinematic reveal animations play once automatically on scroll-into-view (IntersectionObserver, threshold 0.2, unobserve after first fire) then are replayable via a 'Bekijk opnieuw' button using the triggerPulse pattern (remove .is-visible, force reflow via offsetWidth read, re-add via requestAnimationFrame).
- (constraint) prefers-reduced-motion:reduce must snap every animated element to its end state (documented exhaustively in Main.dc.html) — any new animation added later needs its own fallback rule in that block.
- (constraint) Existing CSS/animation system (reveal/reveal-fade/cinematic-reveal, staggered .reveal-d1..d5 delays, SVG stroke-dasharray line-draw, CSS scroll-driven animation-timeline with @supports fallback, the persistent fixed-position viewfinder/Europe-scan layer) is the visual source of truth and transfers into the real build unchanged, regardless of framework chosen.
- (constraint) Known pitfall already fixed once, must not regress: every <svg> root has overflow:hidden by default in the UA stylesheet; content scaled via CSS transform inside an svg stays clipped to the original box unless that svg has explicit overflow:visible.
- (decision) AD-1 Paradigm: static-first content-driven PWA. Nearly all pages/sections are static/prerendered per-trip content; a minimal server-authoritative boundary owns only the mutable shared state (chapter unlocked flags, push subscriptions, packing-list checked state). Binds: all. Prevents: ad-hoc client-side unlock logic reappearing — BUILD_BRIEF flags that Main.dc.html currently has zero conditional logic on 'unlocked' at all, every chapter always renders.
- (decision) AD-2 Content-gating contract: every chapter section on the public page must check trip.chapters[id].unlocked from server-fetched trip state before rendering real content; when locked, render the existing placeholder pattern ('?' / nog een verrassing onderweg). Packing list section is explicitly exempt, always renders. Binds: public rendering layer. Prevents: two builders inventing incompatible gating (CSS display toggle vs server-omitted markup vs client-only flag).
- (decision) AD-3 Mutation boundary: only the authenticated admin route may write chapter 'unlocked' state; the public page and its data-fetch API are read-only. Binds: all write paths. Prevents: a public-reachable toggle/debug endpoint breaking the secrecy premise that is the whole point of the site.
- (decision) AD-4 Push trigger coupling: the same server transaction that flips a chapter's unlocked to true also fans out a Web Push notification (VAPID) to every stored subscription for that trip; no separate or cron-based notification path exists. Binds: admin toggle route. Prevents: notification timing drifting from unlock timing.
- (decision) AD-5 Admin auth: single shared passcode stored as a server env var, checked once, sets an httpOnly server-signed cookie; no user accounts, no OAuth. Binds: admin route protection. Prevents: overbuilding (full user/auth table for one organizer) or underbuilding (BUILD_BRIEF flags there is currently zero auth design, Admin.dc.html is reachable by anyone who knows the URL).
- (decision) AD-6 [ASSUMPTION] Packing list sharing model: one shared trip-wide list; any participant's check/uncheck is visible to everyone, no per-user identity. BUILD_BRIEF explicitly left this open ('overweeg of dit gedeeld moet zijn') — assumed shared because it is the simpler model and nothing else in the brief implies per-user accounts are needed. Binds: packing-list data shape. Prevents: divergent shared-vs-per-device implementations. Revisit with Tim before build if per-person tracking turns out to matter.
- (decision) AD-7 Content-config data shape: a trip is one versioned content entry — {slug, startDate, accentColor, chapters:[{id, order, kind: cinematic|knap, title, time, location, description, svgVariant, unlocked}], packingList:[{id,label}]}. Only 'unlocked' per chapter, push subscriptions, and packing-list checked-state are DB-held mutable rows; every other field is authored static content. Binds: data layer boundary. Prevents: a new trip requiring code changes instead of a new content entry — this is the reusable-template guarantee made concrete. time/location fields must be nullable to allow a chapter to exist with content undecided (Zondag's wadlopen gap).
- (version) [ASSUMPTION][web-verified 2026-08-24] Astro 6 (stable 6.3.1, Astro 6.0 GA Feb 2026) as the site framework: static-first rendering fits the current single-scroll per-chapter pages; small client:load vanilla-JS islands carry toggle/checkbox/replay interactivity without touching the existing CSS/animation code. Source: astro.build/blog/astro-6 and astro-6-beta.
- (version) [ASSUMPTION][web-verified 2026-08-24] @vite-pwa/astro v1.2.0 (Workbox-based, requires Astro >=4.0) generates the manifest + base service worker for installability/offline shell. Push subscription flow and the push/notificationclick event listeners are custom code layered on top — Workbox does not provide push subscription handling itself. Source: npmjs.com/package/@vite-pwa/astro, github.com/vite-pwa/astro.
- (decision) AD-8 [ASSUMPTION][web-verified] Hosting & runtime: Vercel, using Node.js Serverless Functions (not Edge Functions) for the dynamic routes (admin toggle, push subscribe, packing-list write). Binds: all API routes. Prevents: picking Edge runtime and then discovering the web-push VAPID library needs Node's crypto module, which Edge does not fully support.
- (version) [ASSUMPTION][web-verified 2026-08-24][name-corrected] Database: Neon Postgres via the Vercel Marketplace integration. 'Vercel Postgres' as a standalone product was deprecated in June 2025 and all stores were migrated to Neon by Q1 2025 — do not provision under the old product name. Source: neon.com/docs/guides/vercel-postgres-transition-guide, kuberns.com Vercel-Postgres-sunset article.
- (decision) AD-9 Environments: a single Neon branch per environment (a dev branch for local work, the prod branch for the live site) on one Vercel project; no separate staging environment — personal low-stakes project, one deploy target.
- (assumption) [risk, non-blocking] The 'web-push' npm library (VAPID) is the de facto standard for Node push and is used here (AD-8), but its latest published version is roughly 3 years old with no better-maintained alternative surfacing in research. Re-check its state (security advisories, maintenance status, viable alternatives) at implementation start rather than assuming it is still the right call untouched.
- (question) Open product question, not decided here: whether the packing list should ever become per-person (AD-6 currently assumes shared/trip-wide). Revisit with Tim before or during build if it matters.
- (question) Sunday-afternoon program (wadlopen-met-gids) is an intentional content gap, not an architecture concern — AD-7's nullable time/location fields already accommodate a chapter existing before its content is finalized.
- (direction) Deferred: real photo/video assets replacing the current hand-drawn SVG line art — swap-in via the existing content-config asset reference field, no architecture impact.
- (direction) Deferred: the hyperframes (Node/FFmpeg/headless-Chrome) MP4 teaser render pipeline explored earlier — explicitly out of scope for this v1 architecture; a standalone future tool, not part of the PWA runtime.
- (direction) Deferred: v2 two-way interaction (comments/photo uploads) — would need a new mutation surface and likely a real per-user identity model; revisit AD-5 (auth) and AD-6 (packing list identity) together when that scope lands.
- (direction) Deferred: multi-tenant/multi-organizer scaling beyond 'one project, one organizer, new trip = new content entry' — if this ever needs to serve concurrent organizers or a public trip gallery, AD-5 (shared passcode) and AD-8 (single Vercel project) both need revisiting.

- (decision) [fix, web-verification #1+#2] Astro 6.3.1 was stale training data — Astro 7.0 shipped 2026-06-22, and the previously-picked @vite-pwa/astro v1.2.0's peerDependencies cap at Astro ^5.0.0 anyway (real npm-install-breaking conflict, would not have worked with Astro 6 either). Fix: drop the @vite-pwa/astro dependency entirely and hand-write the manifest + service worker instead — the push subscription/notificationclick logic was already going to be custom code on top of Workbox (per the original version note), and a lagging niche integration is not worth pinning the framework major to. Astro itself is now specified as 'latest 7.x stable, pin exact patch at implementation start' rather than a specific patch number, since this space is moving fast enough that a hard-pinned number would likely be stale again by build time.
- (decision) [fix, web-verification #3] web-push npm (3.6.7, ~3yr stale) replaced with PushForge (@pushforge/builder) — actively maintained, zero-dependency, Web Crypto API based, explicitly supports Node.js/Vercel Edge/Cloudflare Workers/Deno/Bun. Removes the Node-crypto dependency that the old AD-8 rationale leaned on.
- (decision) [fix, web-verification #5] AD-8 rationale rewritten: Vercel deprecated standalone Edge Functions outright for new projects (docs updated 2026-07-29), independent of any crypto concern, and consolidated terminology to 'Vercel Functions' with Node.js as the default runtime (Fluid Compute). AD-8 now cites that deprecation as the reason, not the (now-avoidable, since PushForge doesn't need it) Node-crypto argument. Renamed 'Node.js Serverless Functions' to 'Vercel Functions (Node.js runtime)' throughout.
- (decision) [fix, adversarial #1 CRITICAL] AD-7 split into two explicit shapes: TripContent (on-disk static, versioned in git — no unlocked or checked fields, ever, in any form including as a seed default) and TripState (the live API response, merging TripContent with unlocked/packingChecked read from Neon, defaulting false/unchecked when absent from the DB). Closes the redeploy-silently-relocks-chapters risk from a blended schema.
- (decision) [fix, adversarial #2 HIGH + rubric #1 HIGH, combined] AD-2 extended to fully resolve both the state-sync gap and the secrecy/redaction gap: (a) the trip-state API redacts locked chapters server-side — the public GET response for a locked chapter contains only id/order/kind/unlocked:false, never its real title/description/svgVariant/time/location; the static build/prerendered shell itself never embeds locked-chapter content. (b) On receiving a push event, the service worker both shows the notification and broadcasts via postMessage/clients.matchAll to every open tab of that origin, instructing a re-fetch of GET /api/trip/[slug]; the public page re-renders only from that fetch response, never from the push payload directly (payload is notification title/body only). (c) The admin route consumes a separate authenticated variant of the same data that never redacts — consistent with BUILD_BRIEF's 'organizer always sees everything.'
- (decision) [fix, adversarial #3 HIGH] AD-4 extended: on a 404 or 410 response from the push service for a given subscription, the fan-out routine deletes that subscription row before completing. This is the only removal path — no separate cleanup job, no manual unsubscribe route.
- (decision) [fix, adversarial #4 MEDIUM] AD-5 extended: session cookie is long-lived (Max-Age 90 days, not a browser-session cookie) — threat model here is a stranger guessing the admin URL, not session hijacking, and the organizer must not be logged out mid-trip.
- (decision) [fix, adversarial #5 MEDIUM + rubric #4 MEDIUM, combined] AD-3 reworded to explicitly carve out the two public write exceptions: push/subscribe and packing/check are intentionally public and unauthenticated, scoped narrowly to AD-4 and AD-6 respectively, and write nothing outside those specific fields. 'Binds: all write paths' now reads as 'all write paths except these two named exceptions.'
- (decision) [fix, adversarial #6 MEDIUM] AD-6 extended: packing/check takes an explicit desired end-state ({id, checked: boolean}), never a bare toggle. The server performs a plain write, not a read-modify-write, so near-simultaneous edits from different friends resolve by last-write-wins with no lost-update race.
- (decision) [fix, adversarial #7 LOW-MEDIUM] AD-7 clarified: svgVariant is a closed enum over the existing code-defined illustration treatments (vizier/europa, rig/blokarten, kettle/brouwerij, and the two 'knap' treatments). AD-7's 'no code change for a new trip' guarantee covers copy/timing/lock fields only — a genuinely new cinematic illustration treatment is a code addition, not a content-only change; reusing existing treatments for a new trip stays code-free.
- (decision) [fix, adversarial #8 LOW] GET /api/trip/[slug] pinned to always return the full merged TripState (subject to AD-2's per-chapter redaction for the public variant), never a dynamic-only patch.
- (decision) [fix, rubric #2 HIGH] AD-5 extended: the passcode-check route is throttled — a per-IP attempt counter (stored in Neon, same DB already in use) allows max 5 attempts per 15 minutes, returning 429 beyond that. Closes the brute-force gap on the single auth boundary protecting AD-3's protected write path.
- (decision) [fix, rubric #3 MEDIUM] Added a Consistency Convention row: all 4 API routes (trip/[slug], admin/toggle, push/subscribe, packing/check) share one JSON envelope — {ok:true, data} on success, {ok:false, error} on failure.
- (decision) [fix, rubric #5 MEDIUM] AD-7's push-subscription shape gets a tripSlug field; subscriptions are per-trip, and a new trip's content entry requires visitors to re-subscribe (no auto-carry-over of a previous trip's subscribers).
